每條結論可溯源、有資訊完整度分級、矛盾訊號不隱藏。接下來 6 分鐘，我依序說明我們怎麼做到。

## 【主題切合 30%】0:30–2:00（90秒）

命題要求五個能力，我們逐一對應：

**第一，多源整合。**
我們平行抓取六類來源——價格、鏈上、新聞、社群、監管、HOYA BIT 行情。不是單篇摘要，是真正的多源。

**第二，有層次推理。**
三層 Pipeline：Layer 1 抓資料、Layer 2 逐條主張計算信任分數（純演算法，不靠 LLM）、Layer 3 才由 Bedrock 行文。事實、推論、結論分層清晰。

**第三，不確定性與限制說明。**
我們用「資訊完整度分級」取代單一信心數字——高、中、低、棄權。來源不足就誠實標記，不硬給結論。監管沒新事件？我們標「無監管訊號」而不是跳過這個維度。

**第四，可回溯證據管理。**
每條結論帶 claim_id，可一路點回原始來源 URL、取得時間、引用片段。Evidence List 完整符合官方四欄位格式。評審可當場抽查。

**第五，具洞察分析角度。**
我們有矛盾帳本——跨源分歧顯性列出；有來源獨立性圖譜——11 篇新聞去重後只剩 3 個真獨立源；有負空間情報——沉默本身也是情報。

另外，**反作弊鐵則**我們從架構層保證：LLM 收到的是已加權的 TrustedBrief，只能引用 brief 裡的 claim_id，無法引入外部未經驗證的結論。報告裡每句都標明「pipeline 判斷」vs「LLM 行文」，可視覺化驗證。

## 【商業應用 25%】2:00–2:45（45秒）

TrustForge 與 HOYA BIT「AI 不代替決策」的理念完全對齊：

- 我們輸出資訊完整度＋反方證據，不給買賣建議
- 每條結論帶溯源按鈕，資訊透明
- HOYA BIT 行情作為最高信任來源直接整合

商業路徑三步走：
- 近期：整合進 HOYA BIT AI 市場資訊服務，每條分析帶「可信度＋溯源」
- 中期：白標 Trust Layer API，按呼叫次數計費
- 長期：歷史信任分數資料庫，哪些來源長期最準，自適應信譽動態更新

對使用者的價值：解決「資訊太多不知該信誰」的問題，提升決策效率和可採信度。

## 【技術可行 20%】2:45–3:45（60秒）

完整可運行的 Agent 架構，已部署上線。

**AWS 架構：**
- EC2 t3.micro 跑 nginx + Python（公開入口）
- Amazon Bedrock Claude Sonnet（唯一 LLM，合規）
- S3 部署、IAM 最小權限、SSM 無金鑰運維、CloudWatch 日誌
- 全程 AWS，不呼叫任何其他供應商

**Agent 設計：**
Hermes Agent 有 14 個工具，包含來源刷新、快照建構、品質量測、主張抽取、立場分類、報告組裝。不是一次性腳本，是有持續研究、品質自測、自我診斷的完整循環。

**穩定性：**
競賽限 15 分鐘——我們實測 25 到 68 秒完成，餘裕超過 13 倍。任何來源失敗個別降級跳過，不阻塞管線。ExecutionLog 全程追蹤剩餘預算，超時前自動跳過選用步驟，保證報告一定產出。

## 【創意 15%】3:45–4:30（45秒）

四個招牌創意，每個都不是花招，是直接強化信任提煉的：

**一、反事實 A/B 對照**——離線跑 naive RAG 對照組，被假新聞帶偏；TrustForge 壓掉了。一張圖讓非技術評審秒懂價值。

**二、來源獨立性圖譜**——去重偵測＋引用追溯，計票前先去除回音室效應。

**三、矛盾帳本**——不掩蓋分歧，鏈上偏空 vs 社群偏多，顯性列出加權理由。

**四、負空間情報**——把「缺席」當情報。監管無事件、巨鯨異常安靜，都是訊號。

這四個武器的共同特點：都是「非表面摘要的市場洞察」，直接命中評分原文。

## 【可信度說明＋資安】5:10–5:35（25秒）

主辦方可能擔心：使用者看到的信任分數，跟實際可信度會不會有落差？

我們的保證：每個分數都有四維拆解——來源信譽、交叉佐證、時效、操縱懲罰——使用者點開就知道「為什麼是這個分數」。資料不足時自動降級標「低」，不虛報。

資安方面：EC2 無 SSH key 全走 SSM；Bedrock 有 Token Gate，公開 URL 無 token 無法觸發 AI 呼叫；LLM 不能自創結論。不蒐集任何使用者個資。完整資安文件都在 GitHub。

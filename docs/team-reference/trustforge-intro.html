團隊：HurricaneSoft（颶風軟體）— 隊名「中再參與」

比賽要我們做什麼？

做一個 AI Agent（智能助手），它能：

  1. 從多個來源（新聞、社群、鏈上數據、官方公告、價格數據）蒐集加密貨幣資訊
  2. 判斷這些資訊的可信度（哪些可信、哪些可能是假消息或帶風向）
  3. 整合後產出一份帶有證據溯源的分析報告（不是隨便給答案，每個結論都要能追到原始來源）

為什麼不是直接問 ChatGPT？

一般做法：把一堆資料丟給 AI → AI 給你一個摘要 → 你不知道它根據什麼講的

TrustForge 的做法：先把每條資訊打分數（可信嗎？有其他來源佐證嗎？是不是有人在帶風向？）→ 用分數加權後才讓 AI 產出分析 → 每個結論都附上原始證據連結

👉 我們交付的不是「一個答案」，而是「一個你能查證的答案」。

三、系統怎麼運作？（三層架構）

多源輸入 信任提煉 (核心) Agent 編排 / 輸出 ┌─────────────────┐ ┌──────────────────────┐ ┌────────────────────┐ │ 新聞 / RSS │ │ 1. 主張抽取 │ │ Bedrock Agent │ │ 社群 / X │ │ (claim extraction) │ │ - 信任加權融合 │ │ 鏈上 on-chain │ ──▶ │ 2. 來源信譽評分 │ ──▶ │ - 帶溯源生成分析 │ │ HOYA BIT 行情 │ │ 3. 交叉佐證 corroborate│ │ - 反方證據 / 資訊完整度 │ │ 監管 / 公告 │ │ 4. 時效衰減 recency │ │ │ └─────────────────┘ │ ⇒ TrustScore per claim│ └──────────┬─────────┘ └──────────────────────┘ │ ┌──────────▼─────────┐ │ Live Demo (Web UI) │ │ 信任分數 + 溯源面板 │ └────────────────────┘

Layer 1 — Ingestion（資料蒐集層）

從各種來源抓資料，統一格式化成 Document：

來源連接器提供什麼
價格數據prices每日 OHLCV（開高低收量）
新聞news媒體報導、事件
社群socialX/Reddit 討論、情緒、喊單
鏈上數據onchain大額轉帳、交易所流入流出
HOYA BIThoyabit交易所行情（企業數據）
監管公告regulatory政策、合規事件

Layer 2 — Trust（信任提煉層 ★ 核心競爭力）

這是我們跟別人不一樣的地方。把每條資訊的「主張」抽出來，打信任分數：

TrustScore = 來源信譽 × 0.50 + 交叉佐證 × 0.25 + 時效衰減 × 0.15 − 操縱懲罰 × 0.40

Layer 3 — Agent（AI 編排層）

把打完分數的資訊送給 AWS Bedrock（AI 模型），讓它產出帶溯源的分析報告。

四、專業名詞解釋

🎯 核心概念

名詞英文白話解釋
信任分數 TrustScore 一條資訊「可以相信到什麼程度」的分數（0~1）。越高越可信。不是「幣會漲多少」，是「這條消息本身可不可靠」。
來源信譽 Source Reputation 這個來源過去表現如何？官方公告 > 主流新聞 > 匿名社群。鏈上數據（客觀事實）信譽最高 0.95，匿名社群最低 0.35。
交叉佐證 Cross-Source Corroboration 同一件事有幾個「獨立」來源在講？如果只有一個人喊，可信度低；如果三個不同來源都說同一件事，可信度高。
時效衰減 Recency Decay 幣圈資訊過期很快。一週前的消息對今天的判斷影響比較小，會隨時間打折扣。
操縱懲罰 Manipulation Penalty 如果偵測到「帶風向」的跡象（拉盤喊單、機器人大量轉發、情緒極端煽動），直接扣分。
主張 Claim 從一篇文章/消息中抽出的「具體說法」。例如一篇新聞可能包含：「BTC 突破 10 萬」「機構大量買入」兩個主張。
溯源鏈 Provenance 每個結論都能追回到「原始來源 URL + 取得時間 + 引用片段」。讓使用者可以自己去驗證。
資訊完整度 Information Completeness 我們蒐集到的資料「夠不夠完整」來做判斷？如果只有價格數據沒有新聞，完整度就低，結論的信心也應該降低。

🔧 技術名詞

名詞白話解釋
AWS Bedrock Amazon 提供的 AI 模型服務。我們用它來「寫」分析報告。比賽規定只能用這個。
OHLCV Open/High/Low/Close/Volume — 開盤價/最高價/最低價/收盤價/成交量。股票和幣圈的基本價格資料格式。
Agent AI 助手。不是單純問答，而是能「自己去找資料、判斷、產出報告」的自動化流程。
Pipeline 管線。資料從頭到尾經過的完整流程：蒐集 → 信任評分 → AI 分析 → 輸出報告。
Ingestion 資料攝取。把外部來源的資料「吃」進系統裡。
Connector（連接器） 接到外部資料來源的「接頭」。每個來源有自己的連接器。
Dawid-Skene 一個統計方法，用來動態學習「哪些來源比較可靠」。如果某來源經常跟其他可靠來源矛盾，它的信譽會自動降低。
Conformal Prediction 統計校準方法。確保我們說「80% 可信」的時候，真的大概有 80% 的機率是對的，而不是隨便給個數字。
Offline 模式 不連 AWS、不花錢，用本機樣本資料跑完整流程。開發和展示用。
Live Demo 部署在雲端的展示版本，評審可以直接操作。我們的在 EC2 上跑。

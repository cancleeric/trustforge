一、專案是什麼

TrustForge Hermes（信源熔爐）是一個加密貨幣市場分析 AI Agent。它不預測漲跌，而是對多個來源的消息逐條評估可信度，產出帶信任分數和原始出處的市場分析報告。

核心理念：「我們交付的不是一個答案，而是一個你能查證的答案。」

團隊：HurricaneSoft（颶風軟體）4 人｜比賽：2026 雲湧智生 台灣生成式 AI 應用黑客松｜命題方：HOYA BIT｜決賽：8/1–8/2（30 小時）

與一般 Crypto AI 的差異

一般做法TrustForge
多源 → 直接丟 LLM 摘要多源 → 逐條可信度評分 → 信任加權後才進 LLM
來源不分等級來源信譽 + 交叉佐證 + 時效 三維評分
結論無溯源每個結論帶溯源鏈，可點開看原始來源
一句話結論信任分數 + 反方證據 + 溯源鏈，給人決策而非代替決策

四、信任評分公式

TrustScore = 來源信譽 × 0.50
           + 交叉佐證 × 0.25
           + 資料時效 × 0.15
           − 操縱懲罰 × 0.40

來源基礎信譽

來源類型信譽說明
price / onchain0.95客觀事實，鏈上帳本難造假
regulatory0.90官方公告，有法律責任
hoyabit0.85交易所一手行情
news0.65新聞媒體，有編輯把關
sentiment0.50輔助訊號
social0.35匿名社群（最低）

分數代表什麼

範圍意義
0.8 以上多個獨立可靠來源一致、資料新、無操縱跡象
0.5 左右證據不夠充分，或來源一般
0.3 以下來源不可靠、操縱嫌疑、或太舊

六、Hermes Agent 能力

14 個工具、5 條鐵律、自我改善迴圈。

5 條不可變鐵律

  1. 每個價格事實帶 SHA-256 和資料血緣
  2. 每個結論連結到原始來源（source / fetched_at / content_reference）
  3. 反方證據必須保持可見，不得靜默丟棄
  4. 報告必含判斷、依據、校準信心、限制、反轉條件
  5. 只能提出實驗建議，生產變更必須人工批准

自我改善迴圈

measure_quality + replay_history → 量測
  → diagnose_improvement → 診斷提案
  → review_upgrades（Bedrock 對抗審查）
  → 人工批准 → 生產變更

Agent 只量測、診斷、提案。不會自行修改程式、批准或部署。

十、根因分析：為什麼會讓人覺得「空泛」

一句話根因：系統的深度在後端 220 個模組裡，但用戶看到的只有一頁報告和幾個數字。冰山露出水面的部分太小，水下的龐然大物別人感受不到。

問題 1：功能多但實際在跑的少（紙上富貴）

現象具體證據根因改善方向
220 模組但生產只啟用一部分Three-track ❌、AGOS ❌、Backfill ❌、fetch-scheduler ❌工程師思維：先把架構寫完再啟用。對外看起來是「寫了沒用」展示時明確分「在跑的」vs「待啟用的」
版本跳躍 v0.16→v0.27CHANGELOG 中間沒有 v0.17~v0.26短時間大量開發直接合併補段落說明這是內部開發合併
大量模組名稱像「未來規劃」preview_admission_*、quota_key_*部署治理層對評審不重要但佔大量程式碼簡報不提這些

問題 2：信任分數缺乏「證明有用」的證據

現象具體證據根因改善方向
沒有「分高的事後比較準」的回測conformal pseudo-AUC≈0.49（等同隨機）代理訊號沒有預測力——但這不是信任分的目的重新定位：信任分是「資訊品質工具」不是「預測工具」
交叉佐證在離線 demo 大多是 0evidence.json 裡 corroboration: 0.0 居多離線樣本來源太少（每種 1~4 筆），不夠互相佐證用真 Bedrock + 真資料源跑一次
操縱偵測幾乎沒觸發manipulation: 0.0 居多樣本資料是正常文字，當然不觸發準備「正常 vs 被操縱」的對比 demo
Dawid-Skene 動態信譽沒效果只跑 2 次 EM 迭代就收斂5~8 個來源不夠讓 EM 區分好壞誠實說明「需要累積更多歷史才有效」

問題 3：報告制式化，缺乏「真看出什麼」的感覺

現象具體證據根因改善方向
每份報告結構完全相同BTC/ETH/SOL 換名字內容差不多offline 模式用模板生成，沒 Bedrock 敘事用真 Bedrock 跑一次，AI 會寫出具體分析
「獨特洞察」不獨特「聰明錢背離：無法判定」每次都出現離線樣本不滿足判定條件（量沒上升）解釋「無法判定也是有價值的誠實輸出」
方向判斷過度依賴 14 天報酬率Layer 1 幾乎永遠決定方向Layer 2 需要 Bedrock stance 分類；offline 下全降級 neutral展示一次 online stance 分類效果

問題 4：技術深度強但「看不出來」（冰山問題）

現象具體證據根因改善方向
評審只看到一頁 markdown 報告信任層計算過程全在後端前端只顯示結果，不展示過程讓信任雷達圖、證據展開可互動
15 分鐘預算追蹤不可見只在 JSONL 裡，沒人看預算追蹤是給系統用的加執行進度條視覺化
溯源鏈需要主動去挖evidence.json 裡有但要手動開第一眼看不到Demo 時故意點開展示追溯過程

問題 5：新手完全看不懂

現象具體證據根因改善方向
UI 充滿專有名詞「交叉佐證 0.25」「recency decay」開發者預設用戶懂#847 hover tooltip（已開 issue）
星系視覺化炫但不知道代表什麼5 顆行星，大小位置意義不明視覺設計先於功能解釋加 onboarding 引導
報告開頭直接丟數字「信任分 0.63」但 0.63 是高是低？沒有白話語境加「根據 7 個來源，目前偏空，63% 把握」

問題 6：開發節奏問題（最後一天還在加功能）

現象具體證據根因改善方向
7/28~7/30 兩天 +538 commitsmulti-angle、AGOS、comparison、Rust 全在最後三天工程師 deadline 前衝刺本能現在起凍結功能，只穩定和準備 demo
新功能沒有穩定化時間multi_angle_batch_store 88KB 兩天內寫完沒時間 soak test準備 fallback（退回 single-angle）
Windows 不相容asset:eth 路徑在 Windows 爆炸全在 macOS 開發確認團隊 Windows 成員能跑

問題 7：競賽策略面風險

風險說明對策
評審只有 30 秒耐心220 模組但只有 30 秒讓人理解一句話：「我們不預測漲跌，我們幫你分辨哪條消息值得信」
「跟 ChatGPT 問幣圈有何不同」最常見的挑戰「ChatGPT 給你無法驗證的答案；我們給你每條結論的出處和可信度」
被問校準準確率pseudo-AUC 0.49 = 隨機不提預測準確率。定位：「校準讓信心數字更誠實，不是預測漲跌」
大來源造假怎麼辦單一知名來源造假時反應慢誠實說：「需等其他來源反駁才會降分——這是已知限制」
其他隊伍更花俏別人可能有即時看盤、AI 對話差異化是「可查證」——別人給答案，你給證據

改善核心策略

系統深度已經夠了（220 模組、1,811 commits、86% 覆蓋率）。問題不是能力不足，是呈現方式讓人感受不到深度。決賽的勝負在於「30 秒內讓評審理解你的獨特價值」+「3 分鐘內用 live demo 證明」。

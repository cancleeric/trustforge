## 三、精準度分析

「通過閘門」不等於「是加密監管事件」。逐筆檢視 `fsc-news` 的 23 筆：

### 標題命中 7 筆 — 全數為真正的監管事件（精準度 7/7）

| 可見日期 | 標題 |
|---|---|
| 2026-06-30 | 立法院院會三讀通過「虛擬資產服務法」 |
| 2026-05-28 | 預告修正「金融機構及提供虛擬資產服務之事業或人員防制詐欺犯罪危害應遵循事項辦法」 |
| — | 「RWA代幣化小組」完成驗證技術的可行性，下階段重點在法規調適 |
| — | **金管會公告完成洗錢防制登記之提供虛擬資產服務之事業或人員名單** |
| — | 金管會與法務部合作辦理防制虛擬資產遭詐欺利用之教育訓練 |
| — | 金管會說明「虛擬資產保管業務」主題式業務試辦申請情形及後續受理申請事宜 |
| — | 金管會與中央警察大學簽署防制虛擬資產遭非法使用之合作備忘錄(MOU) |

其中「金管會公告完成洗錢防制登記之提供虛擬資產服務之事業或人員名單」
正是 #385 目標所指的 **FSC VASP 名單**——證明來源選對了。

### 僅內文命中 16 筆 — 多為雜訊

例：「高雄專區週年有成　亞資中心再啟新程」、「金融監督管理委員會證券期貨局
每日新聞（115年2月4日）」、「金管會公布我國普惠金融指標114年結果」。
這類文件只在內文某處提及虛擬資產，與加密監管無實質關係。

### 處置

兩者都保留（避免砍掉內文才有實質討論的公告），但以
`Document.meta["gate_match"]` 標記 `"title"` / `"body"`，把精準度訊號交給下游。

**本單不據此調整任何權重**——那屬於 Trust Kernel，#385 明確不做。

## 四、為何 6 個來源 coverage 為 0

| 來源 | 原因 |
|---|---|
| `fsc-penalty` | 498 筆裁罰幾乎全為銀行／證券商一般違規。台灣目前尚無 VASP 開罰案例 |
| `fsc-notice` | 800 筆多為例行「修正各業別金融檢查手冊」，8 筆通過閘門者皆為內文順帶提及 |
| `mops-twse` / `mops-tpex` | 當日重大訊息 snapshot（8 筆／3 筆），台灣上市櫃公司當日無加密相關公告 |
| `twse-punish` / `tpex-punish` | 交易所裁罰專區為財報、會計主管資格等違規，與加密無關 |

這些 0 是**真實的 0**，不是接線失敗——量測時全部 `status=ok`、`degraded=false`。
符合 #385「資料不足時誠實留白」。

## 命題本質（讀三遍）

**不是**單篇新聞摘要，**不是**純技術指標回測。要的是：
1. 真正的**多源整合**（價格 + 鏈上 + 新聞 + 官方公告 + 社群情緒 + 總經/政策）
2. **有層次的推理**：事實 → 推論 → 結論，且說明每項證據如何支撐判斷
3. **對不確定性的清醒判斷**：資料不足 / 訊號矛盾 / 來源可信度有限時，明確指出限制，**不硬給結論**
4. **可回溯的證據管理**：每個關鍵結論都能回溯到具體來源（網址、取得時間、引用片段）
5. **具洞察的角度**：跨來源連結、反方證據、風險因子、非顯而易見的脈絡

## 反作弊鐵則（攸關 30% 主題分）

> 外部服務可用於**取得 / 檢索 / 整理 / 輔助**，但**不得**把第三方已產出的完整市場判斷、交易訊號、買賣建議或分析報告**當主要結果直接提交**。核心判斷、推理鏈、最終報告必須由**我方 Agent 流程**產生，並能說明資料如何被整合、取捨、推論。

→ 設計含義：LLM（Bedrock）負責**推理與行文**，但**判斷結構、證據整合、信任評分**是我方 pipeline 的產物，不是把某分析網站的結論抄過來。

## 幣種池

`BTC / ETH / SOL / BNB / XRP`（當日抽 1 幣 + 1 題）

## 題型池（當日現場抽，無法預知）

| 題型 | 範例 |
|------|------|
| 多源整合 | 分析【幣種】過去兩週表現，整合價格/鏈上/新聞/社群，給整體判斷並說明各類資料一致程度 |
| 假設驗證 | 「【幣種】短期將盤整」——蒐集正反證據，給最終判斷與理由 |
| 比較分析 | 比較【幣種A】與【幣種B】當前市場位置與風險特徵（流動性/關注度/風險敞口）|

**報告模板**（至少）：
1. **結論 / 市場判斷**
2. **關鍵依據**（需對應 Evidence List，說明證據如何支撐判斷）
3. **信心說明**（信心程度、已知限制、資料不足、可能推翻結論的條件）

> 正反方分析 / 風險與不確定性 / 後續觀察重點：非強制，但納入推理品質評分。

## 交付物（4 件）

| # | 交付物 | 格式 | 備註 |
|---|--------|------|------|
| 1 | **分析報告 Final Report** | MD / PDF / HTML / Dashboard | **主要評分對象** |
| 2 | **證據清單 Evidence List** | JSON / CSV / 表格 | 見下方欄位，會抽查 |
| 3 | **執行紀錄 Execution Log** | 任意 | 時戳 + 工具呼叫 + 資料取得 + 流程摘要 |
| 4 | **程式碼與配置 Source/Config** | — | Agent code + 設定 + 執行說明 |

### Evidence 必備欄位（每筆）
- `source`：來源名稱或網址
- `fetched_at`：取得時間
- `content_reference`：引用片段 / 資料區間 / 查詢條件 / 指標數值 / 摘要
- `related_claim`：對應的報告判斷
- 網頁類補 `source_url` + 引用片段；API/CSV/鏈上類補 endpoint / query 參數 / 時間範圍 / 交易對 / 鏈上地址 / 檔名

### 決賽簡報需涵蓋
解題方向、AI 技術應用、數據資料應用、**AWS 架構圖**。
+ Live Demo 部署網址 + 現場執行錄影（含私有 key 流程要完整錄）。

## 執行限制（影響架構設計）

- **執行時間 ≤ 15 分鐘**，超時主辦可停止 / 不採計超時產出。
- 原則上**每隊 1 次正式執行機會**（主辦端故障才可重跑並留紀錄）。
- → 含義：pipeline 要有**時間預算控管**、平行抓取、可快取、失敗降級不崩。

## 基準資料（主辦提供）

- BTC/ETH/SOL/BNB/XRP **近五年 Daily OHLCV**，CSV，UTC 日期。
- 欄位：`date, open, high, low, close, volume`（date=YYYY-MM-DD）。
- 價格單位/交易對以資料包標示為準。
- 其餘（新聞/公告/鏈上/社群/總經/監管）**自行取得**。

### 可用來源（揭露即可）
公開 API（CoinGecko / CryptoCompare / 交易所 API）、公開新聞/公告/研報、公開社群（Reddit / X / 官方社群）、鏈上（Etherscan / Solscan / Dune / 區塊鏈瀏覽器）、付費資料（需揭露，不得當唯一關鍵依據）。

### 來源評分觀察點
類型多樣（價格/鏈上/新聞/情緒）、來源獨立（避免單一來源或同文重複引用）、不過度依賴分析師文章、關鍵結論可回溯。

## 評分標準（總 100% + 加分）

| 權重 | 項目 | 重點 |
|------|------|------|
| **30%** | **主題切合度** | 多源整合 / 證據回溯 / 矛盾處理 / 信心校準 / 限制說明。依賴單一第三方結論 → 扣分 |
| **25%** | 技術可行性 | 可運行 Agent 架構：蒐集→工具調用→整理→推理→報告→紀錄；AWS/framework 架構合理穩定 |
| **20%** | 商業應用性 | 解決資訊分散/雜訊/依據不透明；可讀、可採信、提升理解效率 |
| **15%** | 創意度 | 原創分析方法/資料用法/Agent 設計；非表面摘要的洞察 |
| **10%** | 完成度 | 輸入題目+幣種即完成完整流程，產出報告/Evidence/Log/code 清楚穩定 |
| **+10%** | 加分 | 採用 **AWS Kiro** 作為 AI 整合開發環境 |

→ TrustForge 火力集中在 30%（信任提煉本就是答案）+ 25%（清晰 Agent pipeline）+ 20%（可採信/可回溯），並爭取 Kiro +10%。
